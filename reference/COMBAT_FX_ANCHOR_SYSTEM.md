# 打斗特效物理层 (Combat FX Anchor System)

> **定位**：本文件是 jmcai 的**打斗 / 技能特效物理层**——只负责「特效本身」的物理逻辑：流体怎么成形、粒子在哪迸溅、技能从哪个锚点冒出、撞在什么上、反馈成什么样。
>
> **不负责**动作编排（谁打谁、招式链、强度档位）；那是动作层。两者可叠加使用：先由本层定特效，再把特效段落嵌进完整镜头。
>
> **不改**剧本真值、台词、路由、时序工程与连续性契约；与平台契约或数值真源冲突时，**平台契约优先**。
>
> 配套：词库 `COMBAT_FX_VOCABULARY.md`；失败诊断、收尾约束与跨题材污染词见 `VIDEO_CONTINUITY_FIXES_CHECKLIST.md` §四 / §五。适用平台：Seedance 2.0 / 2.5 / MiniMax H3。

## 一、第一条方法论：流体做主体，粒子做反馈

| 维度 | **流体 Fluid** | **粒子 Particle** |
| :--- | :--- | :--- |
| 本质 | **连续的形态** | 离散的、可崩解的碎片 / 颗粒 |
| 典型形态 | 能量洪流、能量屏障、光丝、剑气刀气、火焰流体 | 固体碎片、气态烟雾、光点能量 |
| 画面表现 | 连贯、可塑性、动态流动感 | 碎石崩裂、烟尘扩散、光点迸溅 |
| 分工 | **做主体**（大招本体、拖尾主体） | **做反馈**（撞击崩裂、氛围点缀） |

**三条实测结论：**

1. **主体必须带材质词**：写「巨型火龙」→ 模型给**实体龙**；写「巨型龙形**火焰流体**」→ 才是要的流体大招。**这一步写错，整条提示词报废。**
2. **拖尾优先用流体**：同场景对比，粒子拖尾与流体拖尾观感差异明显，流体更顺。
3. **想提质感**：流体做主体 + 粒子做点缀（「火焰流体」为主体，周围「火焰粒子」点缀）。

---

## 二、第二条方法论：锚点 + 撞击位置 + 物理反馈（最小三要素）

```text
锚点（技能从哪出来） + 撞击位置（打在哪） + 物理反馈（打完变成什么样）
```

- **锚点优先级最高**：不写锚点，技能会从人物手里或其他地方**乱冒出来**，稳定性骤降。写成**锁定语句**——「特效锚点锁定掌中心」，不是在描述里提一句。
- **撞击位置极灵活**：地面 / 城墙 / 树林 / **敌方身体部位** / **敌方护盾** / **敌方技能（法术对轰）** / 兽群。它让"两个人的打斗"产生**连接**。
- **物理反馈最易忘，但决定打击感**：不写反馈 = 没有打击感。补法：坍塌 + 飞射 + **不规则形状**（规则形状显假）。

## 三、撞击 vs 接触（必分清）

| 类型 | 例子 | 反馈写法 |
| :--- | :--- | :--- |
| **撞击位置** | 龙形流体砸向地面 / 城墙 | 撞击中心 + 碎石 / 碎砖崩裂（粒子） |
| **接触位置** | 毒雾笼罩古城废墟（覆盖，不是砸） | 接触面出现**被腐蚀脱落**效果 |

> 写之前先问自己：**这是"打下去"还是"盖上去"？** 两者的物理反馈完全不同。

---

## 四、六要素结构公式（写完整条特效的骨架）

```text
镜头机位 + 流体 + 粒子 + 光效 + 撞击/接触位置 + 物理反馈
```

- **必写**：流体、粒子（缺一个就没有特效）
- **建议写**：撞击/接触位置、物理反馈（决定准确度与打击感）
- **可加**：光效（写好流体 + 粒子 + 环境氛围词，色彩效果其实已自动出来）
- **可不写但必须懂**：镜头机位（不写模型也会给合理景别，**要精确控制就得自己写**）

## 五、通用动作四件套

```text
压缩 → 蓄能 → 膨胀 → 吞吐
```

- 火焰流体：火焰向内压缩 → 蓄能发光 → 骤然膨胀 → 向前吞吐成洪流
- 强光提质感：光体压缩成核 → 蓄能变色 → 膨胀炸开 → 吞吐成冲击波
- **变身 / 大招类的动作节奏就靠这四个词。**

## 六、特效段落写作规范（本层核心产出）

无论哪个模型，**特效部分尽量写满这 5 句**：

| # | 必写句 | 反例（禁） | 正例 |
| :--- | :--- | :--- | :--- |
| 1 | **主体形态** | 「巨型火龙」 | 「巨型龙形**火焰流体**」 |
| 2 | **锚点位置** | 「释放技能」 | 「自**掌中心**凝出雷球」「技能自**身后**浮现」 |
| 3 | **撞击 / 接触位置** | 「打出去」 | 「撞击中心为**城墙**」 |
| 4 | **粒子迸溅** | 「很炫酷」 | 「迸溅**红色火星粒子**与**黑烟粒子**」 |
| 5 | **物理反馈** | 「被击飞」 | 「城墙**大面积碎砖崩裂扬尘**，**形状不规则**」 |

**另有两条距离参数必须明写**：**高度 / 方位**——「悬于**百米高空画面左上方**」+ **仰视视角**，不写就翻车（技能位置太低）。

---

## 七、双人 / 多人：景别 + 构图 + 距离（防"低智镜头"）

- **单人**：可以不写景别，生成还算稳定。
- **双人 / 多人**：**必写**景别与构图，否则不约束时一个场景会直接冒出两个人、且没有距离感，镜头看起来很"低智"。
- 写法参考：中近景（腰以上）· 远景（两人位于画面两端，距离上百米）· 对角构图（一人左下地面、一人右上角）· 仰拍 / 俯拍 · 跟随运镜。

## 八、特效如何嵌进 jmcai 各平台契约

本层只产**特效段落**，封装时遵循 jmcai 既有平台契约：

- **Seedance（2.0 / 2.5）**：遵守 `SEEDANCE_25_PRODUCTION_SPEC.md` 与 `STYLE_BLOCK.md`；时间控制按平台能力（2.5 用时间戳秒级锚定）；特效段写进画面描述；负向约束默认都加（见 `VIDEO_CONTINUITY_FIXES_CHECKLIST.md` §五）。
- **MiniMax H3**：特效写入英文 `detailed_description` 的镜头行。**关键风控：能量只从接触点爆发**，不能是自由漂浮的光束或常驻光环——能量是**命中的结果**，不是命中的替代品（写实街战模式下**完全没有能量**，冲击纯物理：灰尘、碎屑、闷哼）。字段与配对见 `MINIMAX_H3_DUAL_PROMPT_CONTRACT.md`。

## 九、参考图（最小资产）

- 最小资产只要**人物主视图**；要统一形象（固定的龙 / 加人物）再补场景图与多视图。资产出图见 `PROMPT_TEMPLATE_ASSET_EXPANSION.md`。
- Seedance：`@图片1` = 主角、`@图片2` = 对手、`@图片3` = 场景；H3：`<Subject 1> whose appearance comes from <Picture 1>`（不给图片单独开一行）。

## 十、自检

- [ ] 流体主体带**材质词**（不是实体名词）
- [ ] 锚点写成**锁定语句**（掌心 / 武器 / 地面 / 身后）
- [ ] 撞击或接触位置明确，且区分了"撞击 / 覆盖接触"
- [ ] 物理反馈 ≥3 项，且含「不规则形状」
- [ ] 高度 / 方位明写（需要时）+ 视角写成
- [ ] 双人 / 多人：景别 + 构图 + 距离都写了
- [ ] 特效不遮主体，粒子只沿武器 / 碰撞点 / 攻击轨迹
- [ ] 结尾不写"缓缓收势 / 光芒渐熄 / 定格摆姿势"（见 `VIDEO_CONTINUITY_FIXES_CHECKLIST.md` §五）
- [ ] H3：能量只从接触点爆发，不是自由漂浮的光束
