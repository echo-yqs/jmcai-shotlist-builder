# 短剧结构工程：单集节拍、钩子与类型包 (Short-Drama Structure & Genre Packs)

本文件是 JMCAI Shotlist Builder 的**上游故事规划层**：它把"逐个单元拍准"提升为"整集抓人"。它只作用于**单元蓝图（`H3_UNIT_BLUEPRINT`）之前的 beat 规划**，不改变以下任何权威：

- 剧本正文与用户当前修正（内容真值）；
- 台词原文、顺序与标点（逐字保留，不因节奏改写）；
- H3 路由（I2VA / FL2VA / L2VA / Ref2VA）与上传槽位契约；
- 时长、口型与时序工程（`MINIMAX_H3_TIMING_ENGINEERING.md`）；
- 边界台账、双稿契约与三大 Linter。

当本文件与上述权威冲突时，一律以上述权威为准。本文件**不新增** H3 提示词字段；`EPISODE_BEAT_MAP` 是内部规划产物，不是输出格式。

## 0. 启用条件

在进入 `H3_UNIT_BLUEPRINT` 之前先建 `EPISODE_BEAT_MAP`，当且仅当满足其一：

- 素材是**分集/竖屏短剧**（付费短剧、小程序剧、红果／抖音／快手短剧）；
- 用户明确要求"更抓人、更爽、留钩子、卡点强"；
- 任务是**多集**且需要跨集悬念管理。

单条广告片、单场景文艺短片、MV 不强制启用；但"钩子是否落在前 3–6 秒""结尾是否有可记住的稳定画面"两条基本原则仍然适用（与 `MINIMAX_H3_TIMING_ENGINEERING.md` 的稳定尾幅、`MINIMAX_H3_CINEMATIC_RHYTHM.md` 的 `afterimage` 一致）。

## 1. 商业结构决定戏剧结构

竖屏短剧的物理约束不是审美偏好，而是留存与付费的工程条件：

| 约束 | 数值 | 对结构的要求 |
| --- | --- | --- |
| 单集时长 | 60–120 秒（主流 60–90 秒） | 一集 = 一个完整的"小反转弧"，不能是半场戏 |
| 首屏留存窗口 | 前 3–6 秒 | 第 1 个单元必须交付钩子，禁止用环境空镜慢开场 |
| 反转频率 | 每 20–40 秒一次小反转／信息颠覆 | 一集至少 1 个反转，长集 2–3 个 |
| 集尾 | 最后 3–5 秒 | 必须留卡点（悬念／新威胁／身份暴露／反转前一刻） |
| 付费点 | 常在首集末或第 1–3 集末 | 卡点强度最高的位置，钩子密度最高 |
| 画幅 | 竖屏 9:16（见 `STYLE_BLOCK.md` 的画幅覆盖） | 构图应按竖屏设计，不是把横屏裁窄 |

> 这些是**结构约束**，不是对模型能力的断言。具体上传与生成仍按平台规范执行。

### 竖屏构图法（9:16）

竖屏不是把横屏裁窄；它有自己的取景逻辑：

- **画幅**：9:16。禁止先做横屏构图再裁切；一切景别与走位按竖屏设计。
- **安全区**：顶部约 8%、底部约 12% 可能被平台 UI 遮挡，关键信息（脸、字幕底图、道具落点）避开这两带。
- **景别更近**：竖屏下 `MS` 已接近横屏 `MCU`，`CU/ECU` 冲击更强；慎用远景大全景（人物过小）。
- **压缩头顶留白**：竖屏最忌头顶大片空白；让人物纵向填满，眼睛落在上三分线附近，而不是把人物塞在下半部。
- **中心构图与对称**：竖屏纵向狭长，适合中心构图与中央对称（打脸、对峙、仪式）；横向元素稀缺。
- **双人调度**：竖屏横向放不下两人并排。改用**前后景纵深**、过肩、上下分层，或干脆正反打；不要硬挤并排。
- **运镜方向**：横向运镜空间小，倾向**纵向**（推近、升降、轻下摇）与受控微动；大幅度横摇在竖屏里容易失控。
- **环境线条**：善用纵向线条（门框、走廊、楼梯、雨幕）强化纵深。
- **群戏**：竖屏难容纳多人大全景；用反应镜头接力与特写交代群体态度（与 §7.1 的"围观者反应波"一致）。

> 输出时把 `9:16` 作为声明画幅记录：Seedance 的 footer 由 `21:9` 改 `9:16`，H3 不带 footer。

## 2. 单集 beat 模型（`EPISODE_BEAT_MAP`）

一集拆成 5–7 个 beat。每个 beat 是"一个变化"，不是"一段画面"。

| # | beat | 位置 | 功能（观众/角色发生的改变） | 时长占比 | `unit_role` 标签 |
| --- | --- | --- | --- | --- | --- |
| 1 | 钩子 Hook | 0–6s | 抛出最反常/最冲突的一帧事实，制造"必须看下去"的问题 | 5–10% | `hook` |
| 2 | 情境与目标 Establish & Want | 6–25% | 主角是谁、此刻想要什么、谁挡在前面 | 15–20% | `establish` |
| 3 | 加压 Escalate | 25–60% | 阻碍升级、代价变大、退路被切断 | 30–35% | `escalate` |
| 4 | 反转 Reversal | 60–80% | 信息/权力/关系翻转（打脸、揭穿、底牌） | 15–20% | `reversal` |
| 5 | 高潮 Climax | 80–95% | 主角用行动兑现反转，情绪释放 | 10–15% | `climax` |
| 6 | 卡点 Cliffhanger | 95–100% | 留下新的不平衡，逼向下一集 | 3–8% | `cliffhanger` |

- 短集（60 秒）可合并 #2 与 #3、#4 与 #5，但**钩子与卡点不可省**。
- 每集只服务**一条**主关系线与**一个**核心问题；副线只能加压，不能另开山头。
- 集与集之间：上一集 `exit_state` 的情绪残响就是下一集的 `opening_pressure`。

## 3. 钩子库（前 3–6 秒怎么抓人）

| 钩子类型 | 机制 | 典型画面 |
| --- | --- | --- |
| 颠覆预期 | 先给最常见场景，再用一个反常事实打破 | 婚礼进行中，新娘掏出离婚协议 |
| 悬念前置 | 先给"结果"再倒叙问"为什么" | 主角跪地满脸血，画外一声"三亿，你赔得起？" |
| 身份错位 | 以小博大／以贵扮贱的落差 | 保安制服下亮出军功章 |
| 危险逼近 | 明确的物理或时间威胁 | 倒计时、逼近的车灯、举起的手 |
| 情绪极值 | 直接给最强情绪的一帧 | 一巴掌落下、泪在眼眶未落 |
| 信息炸弹 | 抛出改变全部前提的一句话 | "孩子，不是你的。" |

钩子必须是**本集真实会发生的事**，不能是预告式剪辑欺骗；否则第一集就失去信用。

## 4. 卡点库（最后 3–5 秒怎么留人）

| 卡点类型 | 机制 | 收尾形态 |
| --- | --- | --- |
| 揭示前一刻 | 观众知道真相、角色还不知道 | 门开一条缝、信纸露一角 |
| 新威胁登场 | 威胁升级，主角刚放松 | 电话响起、黑影入画 |
| 反转未完成 | 动作进行到一半切黑 | 手停在半空、话说到一半 |
| 承诺/宣战 | 主角定下下一步目标 | 站起、攥拳、转身 |
| 代价显现 | 胜利后暴露新代价 | 伤口渗血、远处目光 |
| 静默反差 | 极静之后一个异常 | 全场寂静，只有一声轻响 |

卡点必须落在**稳定可读的尾态**上（0.8–1.0 秒稳定尾幅，见时序工程），不能靠未完动作的混乱帧。

## 5. 反转密度与爽点曲线

- **反转密度**：每 20–40 秒一次"小翻转"（认知/权力/信息的改变）；一集至少 1 次、长集 2–3 次。密度过低 = 温吞；过高 = 观众来不及反应，连续反转会互相抵消惊喜。
- **爽点曲线**：单集情绪应呈"低起—阶梯加压—一次大释放—余震留钩"。禁止平铺直叙的多段同等强度高潮（与 `MINIMAX_H3_TIMING_ENGINEERING.md §一 SCENE_RHYTHM_MAP` 的"连续三到五镜不得无递进重复同一情绪温度"同源）。
- **释放与克制的分工**：`MICRO_BEATS.md` 等表演谱偏克制（默认不哭、抑制），适合加压段与反转前的暗流；**高潮与爽点必须给"释放档"**（见 §7），否则模型会把类型高潮演成文艺闷戏。
- **信息节流**：反转靠"延迟揭示"制造，不靠旁白解释。谁在何时知道什么（信息差）是打脸与揭穿的发动机；用景别、焦点、剪辑遮挡来延迟，而不是用台词说破。

## 6. beat → H3_UNIT 映射

- 每个 beat 由 **1 个或多个 `H3_UNIT`** 承载。一个 `H3_UNIT` 仍然只满足 `MINIMAX_H3_LONG_SCRIPT_UNITS.md §3` 的"一次微型关系变化 + 一条主动作链 + 一个明确出口"。
- `EPISODE_BEAT_MAP` 为每个单元标注一个 `unit_role`（`hook`/`establish`/`escalate`/`reversal`/`climax`/`cliffhanger`）。`unit_role` 决定该单元**优先交付哪种新信息或情绪**，但不改变其内部镜头设计规则。
- beat 边界与 `H3_UNIT` 边界不一致时：**戏剧切分优先于 beat 计数**——宁可让一个 beat 跨两个单元，也不要把两个独立微型关系变化塞进一个单元。
- 钩子单元与卡点单元通常最短（3–8 秒），可能触发 5–9.99 秒例外；必须写明 `duration_exception_reason`（见 `MINIMAX_H3_LONG_SCRIPT_UNITS.md §4` 与场景真值规范）。
- 每个单元的 `exit_state` 必须能直接成为下一单元 `opening_state`；跨集时同样成立。

## 7. 类型包（Genre Packs）

按题材选择对应类型包，作为 beat 与情绪档的默认模板；用户明确指令优先。每个类型包给出：核心引擎 / 主角—反派 / 必备节拍 / 视听语法 / 情绪回收 / 常见翻车。

### 7.1 爽文打脸（逆袭打脸）
- **核心引擎**：被轻视 → 隐藏实力 → 当众翻盘。
- **主角—反派**：主角"扮弱/被踩"；反派"嚣张/势利"，负责提供打脸靶子。
- **必备节拍**：羞辱 hook → 加压（外人围观、主角被逼死角）→ 打脸反转（底牌/身份/实力暴露）→ 围观者反应波 → 卡点（更高层对手登场）。
- **视听语法**：竖屏中心构图、打脸瞬间用特写 + 硬切、围观者反应镜头接力（错愕→谄媚）。
- **情绪回收**：**释放档**——主角从容不迫，反派狼狈；围观者的态度反转是爽点的最重要证据。
- **常见翻车**：打脸太早（未见足够压迫）；围观者无反应；反派不够可恨。

### 7.2 战神 / 赘婿 / 身份揭秘
- **核心引擎**：真实身份被隐藏 → 误认与羞辱 → 身份揭穿。
- **必备节拍**：被误认 hook → 隐忍加压 → 线索逼近（信物、旧识、高层求见）→ 揭穿反转 → 旧羞辱者崩塌 → 卡点（更大势力察觉）。
- **视听语法**：身份信物（军功章、袖扣、印章）用焦点锁定插入镜头；揭穿用"一物定乾坤"的近景落点。
- **情绪回收**：从隐忍到**短暂释放**，但揭穿后主角仍克制更高级；释放主要给反派与围观者。
- **常见翻车**：信物没提前埋；揭穿靠旁人台词说破而非画面证据。

### 7.3 重生 / 穿越 / 先知
- **核心引擎**：主角知道未来 → 提前布局 → 篡改命运。
- **必备节拍**：既视感 hook → 利用先知布局 → 对手按旧剧本反应 → 现实偏离反转 → 新变数 → 卡点（命运反噬或新敌人）。
- **视听语法**：用同一构图/台词在不同时间层复现以标示"已知"；时间层切换必须显式标注，单元不得跨时间层（见 `MINIMAX_H3_LONG_SCRIPT_UNITS.md §3`）。
- **情绪回收**：掌控感（冷静）与失控一瞬的反差。
- **常见翻车**：闪回/前世与现世混在同一单元；先知优势没有付出代价。

### 7.4 虐恋 / 虐心
- **核心引擎**：相爱相杀、误会与牺牲、以痛证爱。
- **必备节拍**：亲密 hook → 误会/背叛加压 → 隐忍（主角独自承受）→ 真相反转 → 追悔 → 卡点（无法挽回的代价）。
- **视听语法**：克制的暗流表演（`MICRO_EXPRESSION.md`）+ 高潮**释放档**（崩溃、泪落、跪、嘶吼）；留白与静默制造痛感。
- **情绪回收**：**释放档**是主菜——这是多数克制型表演谱**必须例外**的类型；高潮不给释放会彻底失效。
- **常见翻车**：全程只迫害不释放；误会靠旁白解释而非行动证据。

### 7.5 悬疑 / 复仇
- **核心引擎**：埋线索 → 逐层揭开 → 复仇兑现。
- **必备节拍**：谜题 hook → 调查加压 → 假答案诱导 → 真相反转 → 复仇高潮 → 卡点（漏网者或更大阴谋）。
- **视听语法**：信息节流——用遮挡、焦点、画外声延迟揭示；道具/环境做线索载体；关键线索给独立插入镜头。
- **情绪回收**：真相揭晓的震惊 + 复仇兑现的冷冽满足。
- **常见翻车**：线索不埋或埋太浅；反转靠新信息硬塞而非前文伏笔。

### 7.6 甜宠 / 都市情感
- **核心引擎**：欢喜冤家 → 相处升温 → 确认关系。
- **必备节拍**：甜/误会 hook → 摩擦升温 → 关键事件（护短、吃醋、共患难）→ 感情确认反转 → 卡点（外部阻力或误会）。
- **视听语法**：眼神与距离的微差、近景微表情、反应镜头；光调偏暖（阴影侧规则按 H3 例外执行，见 `STYLE_BLOCK.md`）。
- **情绪回收**：轻甜为主，允许一次性小爆发（表白、护短）。
- **常见翻车**：只撒糖无阻碍；两人关系无实质推进。

## 8. 情绪释放档（服务短剧节奏）

克制是高级审美，但短剧的类型需求要求**在正确的 beat 上明确授权释放**。规则：

- 只在 `reversal` / `climax` / `cliffhanger` 三类 `unit_role` 上启用释放档；`establish` / `escalate` 默认仍走克制谱。
- 释放不等于浮夸：仍遵守 `MICRO_BEATS.md` 的"用具体肌肉/呼吸/眼泪/声音变化代替情绪形容词"，只是允许更强的可见结果（泪落、嘶吼、下跪、耳光、崩溃的呼吸）。
- 释放必须有**触发**和**代价**，不能凭空出现、一镜即恢复（与 `HELL_GRIND_ADAPTATION.md`"强动作之后保留代价"一致）。
- 释放的幅度按类型包取值：爽文/战神偏"从容释放"，虐恋偏"失控释放"，甜宠偏"小爆发"。

## 9. 交付字段（内部规划，不进入提示词）

`EPISODE_BEAT_MAP` 每集一行起，至少包含：

| 字段 | 内容 |
| --- | --- |
| `episode_id` | 集编号 |
| `declared_runtime` | 声明单集时长（与场景真值对账） |
| `core_question` | 本集唯一核心问题 |
| `hook` | 钩子事实 + 类型 + 所在单元 |
| `beats[]` | 每 beat：`beat_id`、`role`、`function`、`owned_source_beats`、`reversal_type`（如有）、`emotion_tier`（`克制`/`释放`） |
| `reversal_points` | 本集反转时点与类型 |
| `cliffhanger` | 卡点类型 + 尾态 |
| `exit_emotion` | 本集出口情绪（作为下一集 `opening_pressure`） |

`beats[]` 的 `owned_source_beats` 必须与 `SOURCE_BEATS` 一一闭合，不得出现无主的 beat 或未覆盖的源节拍。

## 10. 自检清单

- [ ] 首次出现能抓住人的事实是否落在前 3–6 秒（`hook` 单元）？
- [ ] 本集是否有且只有一个核心问题与一条主关系线？
- [ ] 是否至少有 1 次清晰反转，且反转有时间、有触发、有代价？
- [ ] 集尾是否留下**稳定可读**的新不平衡（卡点），而不是未完动作的混乱帧？
- [ ] 爽点曲线是否是"低起—阶梯加压—一次大释放—余震留钩"，而非多段同强度平铺？
- [ ] 是否在正确的 `unit_role` 上授权了释放档？释放档是否有触发、有代价、未提前恢复？
- [ ] 类型包的关键必拍节拍是否齐备？常见翻车是否已规避？
- [ ] 所有 beat 与 `SOURCE_BEATS` 是否闭合？台词是否仍逐字保留、未因节奏改写？
- [ ] `exit_state` 是否可直接作为下一单元/下一集的 `opening_state`？

结构清晰不等于成片好看；本清单只保证"设计可执行"，实际效果仍以成片验收为准。
